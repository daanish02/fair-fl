## Details

### Architecture

One file per strategy (`code/src/fairfl/strategies/<name>.py`), one YAML config per
strategy (`code/src/fairfl/configs/<name>.yaml`), CLI `--set key=value` overrides.
Adding a new strategy later needs only a new file, confirmed by testing a throwaway one.

### Paper extractions

Each of the 8 papers in `docs/impl-papers/` was read fully and transcribed into a
matching `.txt` file (same folder) with exact equations, hyperparameters, and result
tables — so configs and thesis writing don't need to re-open the PDFs, and nothing not
stated in a paper was guessed.

### Bugs found and fixed this week

- Momentum hardcoded at 0.9 everywhere; FCFL wants 0.5, FedCDA wants 1e-4 — now a real
  config field.
- No partial-client-participation existed; FedCDA/FCFL/FedMut all specify sampling a
  fraction of clients per round — added `clients_per_round`.
- `FairWeightClient.fit()` crashed on a missing parameter after an interface change —
  found and fixed mid-run.

### Integrity audit (code in `code/src/fairfl/`, not yet fixed)

Checked whether results from this code would be honest and reproducible by someone else.
Ordered by how much they affect our claims.

**Affects every strategy**

- **Unseeded model start** (`train/engine.py:146`). Only the data split and shuffling are
  seeded; `torch.manual_seed` is never called, so each run and each strategy starts from
  different random weights. The Colab notebook also turns on `cudnn.benchmark`, which adds
  small GPU run-to-run differences. Single-seed comparisons are mixed up with this noise.
- **Per-client test sets don't match client training data** (`train/engine.py:140`). The
  test set is split with its own separate Dirichlet draw. For seed 0 the train-vs-test
  label mix per client differs by a total-variation distance of 0.32 to 0.78. So "client c
  accuracy" is the global model on a random skewed slice of the test set, not a measure of
  how client c was served. Comparisons between strategies still use identical slices.
- **Saved configs are incomplete** (`notebooks/_build.py:149`, `cli.py:46`). No git commit
  is recorded, strategy defaults filled in by code aren't saved, and a misspelled config
  key would be silently ignored but still look applied. The notebook pulls GitHub `main`,
  which can differ from uncommitted local code. Older baseline JSONs (`code/results/`) use
  a pre-refactor format without model/momentum/weight-decay fields.

**Strategy-specific**

- **FCFL uses the test set during training** (`train/engine.py:165-171`). Its unfairness
  queues are driven by client accuracy measured on the same test split later used to report
  results. The paper uses each client's local data. Inflates FCFL's fairness numbers.
- **FedFDP's fairness clip probably never acts** (`clients/fedfdp.py:83`). With clip
  C=0.1 the privacy bound C/||g|| almost always wins over the fairness term 1+lambda*Delta.
  Archived MNIST runs with lambda=0 and lambda=0.01 gave identical accuracy
  (0.8902000188827515). Also, the coefficient can go negative (gradient ascent on
  well-fit samples) since FedFDP has no floor at 0, unlike FedFair.
- **FairWeight can't run with ResNet18 and is half inactive** (`clients/fairweight.py:36`,
  `:58`). Shape mismatch (BatchNorm buffers included on one side only) crashes it. Its
  "animal labelled as class 0" check is always empty because class 0 (airplane) is a
  vehicle, and the remaining check compares airplanes with cars, unrelated to the group
  label. Weights flagged by every client get set to zero.
- **LogoFair's test-time rule sees the true class** (`strategies/logofair.py:168`). The
  vehicle/animal attribute it takes as input is computed from the true label. Its per-round
  accuracy curve is also plain FedAvg, since post-processing only happens after training.
- **signSGD config isn't the paper's method** (`strategies/signsgd.py:20-40`). It votes on
  the sign of 5 epochs of local change rather than one gradient, takes only 30 steps of
  0.001 in total, and also sign-steps BatchNorm statistics. Accuracy is pushed down.
- **FairRFL** does detection and the q-FFL step layer by layer rather than on the whole
  model (`strategies/_qffl_step.py`, `strategies/fairrfl.py:72-78`). Small deviation.
- **Config comments out of date:** `fedmut.yaml` and `fcfl.yaml` say the model is
  cnn_cifar but run resnet18. FedMut's paper value for ResNet-18 is beta_0=0.5 (config has
  0.3). FCFL's paper "server momentum 0.5" is applied as client SGD momentum.
