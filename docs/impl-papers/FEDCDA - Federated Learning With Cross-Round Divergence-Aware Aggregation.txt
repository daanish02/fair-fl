2. PROBLEM SETUP / WHAT THE PAPER IS SOLVING
================================================================================
Standard FL aggregation (FedAvg) averages client local models from only the
CURRENT round. Because client data is statistically heterogeneous (non-IID),
local models trained in the same round from different clients can diverge
substantially from one another, so the aggregated global model can end up far
from any individual client's local optimum and lose client-specific data
knowledge. The paper's key empirical premise is that because clients receive
different global models in different rounds and deep neural networks are
non-convex (multiple local optima / saddle points), a given client's local
models across DIFFERENT rounds may actually be closer to each other (lower
divergence) than local models from DIFFERENT clients in the SAME round.
FedCDA exploits this: instead of aggregating only same-round local models, it
selectively aggregates local models drawn from multiple recent rounds (a
per-client cache of K recent local models), choosing the combination that
minimizes cross-client divergence, so the resulting global model stays close
to each client's own learned local optimum and better retains everyone's data
knowledge.

3. ALGORITHM
================================================================================

--- Base FL objective (Eq. 1) ---
min_w F(w) = (1/N) * sum_{n=1}^{N} F_n(w),   s.t. F_n(w) = E_{xi~D_n}[f_n(w; xi)]
N = number of clients, D_n = data distribution of client n, f_n(w;xi) = loss
on sample xi (or a mini-batch loss).

Assumptions used throughout (stated as Assumptions 1-3):
- Assumption 1 (L-smoothness): F_n is L-smooth with Lipschitz constant L>0,
  i.e. ||grad F_n(w) - grad F_n(w')||_2 <= L ||w - w'||_2 for all w, w'.
- Assumption 2 (Bounded Variance): local stochastic-gradient variance per
  client bounded by sigma_l^2: E(||grad f_n(w) - grad F_n(w)||^2) <= sigma_l^2.
  Global variance of gradients among clients bounded by sigma_g^2:
  (1/N) sum_n ||grad F_n(w) - grad F(w)||^2 <= sigma_g^2.
- Assumption 3 (Bounded Gradient): E(||grad f_n(w)||^2) <= M^2 for all w.

--- Step 1: upper-bound via L-smoothness (Eq. 2) ---
Applying Assumption 1 (L-smoothness) to each F_n gives an upper bound on the
objective:
F(w) = (1/N) sum_n F_n(w)
    <= (1/N) sum_n [ F_n(w^n) + grad_{w^n} F_n(w^n)^T (w - w^n) + L ||w - w^n||_2^2 ]
(Eq. 2)

--- Step 2: the cross-round selection objective (Eq. 3) ---
Given the set of K recent cached local models per client,
W_t^n = {w_{t1}^n, ..., w_{tK}^n}, the server minimizes the RHS of Eq. 2 over
BOTH the global model w AND the choice of which cached local model to use per
client:
min_{w in R^d, w^1 in W_t^1, ..., w^N in W_t^N}
  (1/N) sum_n [ F_n(w^n) + grad_{w^n} F_n(w^n)^T (w - w^n) + (L/2) ||w - w^n||_2^2 ]
(Eq. 3)
This is strongly convex in w for any fixed combination of local models w^n.

--- Closed-form global model given selected local models (Eq. 4) ---
w = (1/N) sum_n w^n  -  (1/(LN)) sum_n grad_{w^n} F_n(w^n)
(Eq. 4)
So, given Eq. 4, Eq. 3 reduces to a COMBINATORIAL optimization problem over
which cached local model w^n to pick per client (model selection), since w is
then determined by the chosen w^n's.

--- Approximation: drop the full-gradient term (Eq. 5 / Eq. 6) ---
Computing the full gradient grad_{w^n} F_n(w^n) on each client's local
dataset is expensive (extra computation + communication). The paper notes
that each local model w^n tends to nearly reach a local optimum or saddle
point w^{n,*} (especially late in local training / with many local epochs),
so it approximates grad_{w^n} F_n(w^n) ~= 0. Problem (3) is then
re-formulated as:
min_{w^1 in W_t^1,...,w^N in W_t^N}  (1/N) sum_n F_n(w^n) + (L/(2N)) sum_n ||w - w^n||_2^2,
  s.t. w = (1/N) sum_n w^n
(Eq. 5)

Equation 5 is equivalent to (via sum (x_i - xbar)^2 = sum x_i^2 - N*xbar^2):
min_{w^1,...,w^N} (1/N) sum_n F_n(w^n) + (L/(2N)) sum_n ||w^n||_2^2 - (L/2)||w||_2^2,
  s.t. w = (1/N) sum_n w^n
(Eq. 6)

Eq. 5 shows the selection criterion directly: pick cross-round local models
with MINIMAL DIVERGENCE among each other, i.e. minimize
Var(w^n) = (1/N) sum_n || w^n - wbar ||_2^2 (variance across the N selected
local models), particularly when the F_n(w^n) loss terms are already small
across clients. Eq. 6's form (||w^n||^2 term) lets the l2 norm of each w^n be
cached once computed, avoiding repeated computation, reducing cost versus
directly computing variance.

--- Computational cost of brute-force selection (Proposition 1) ---
Proposition 1: The computation complexity of solving (6) is O(K^N) and the
memory cost is KNC, where C denotes model size. (Exponential in N — not
affordable at scale.)

--- Reduction step 1: partial-client selection (Eq. 7, Proposition 2) ---
To reduce cost, only the P clients n in P_t that participate in the CURRENT
round t have their cached local model selected/optimized; local models of
non-participating clients (n in N - P_t) are FIXED to whatever was selected
in previous rounds:
min_{w^n in W_t^n, for all n in P_t}
  (1/N) sum_{n in P_t} L_n(w^n)  +  (1/N) sum_{n in N - P_t} L_n(w^n) [fixed in current round]
  - (L/2) ||w||_2^2,
where w = (1/N) sum_{n=1}^{N} w^n and L_n(w^n) := F_n(w^n) + (L/2)||w^n||_2^2.
(Eq. 7)
Proposition 2: The computation complexity of solving (7) is O(K^P) and the
memory cost is KPC. (P = number of participating clients per round, typically
much smaller than N, e.g. the paper samples 20% of clients, so this is a
major reduction from O(K^N).)

--- Reduction step 2: batch-based (stochastic greedy) selection (Eq. 8, Proposition 3) ---
To reduce cost further, the P participating clients are randomly grouped into
B equal-size batches: P_t = P_t^1 ∪ ... ∪ P_t^B. Local models are selected
batch by batch: when selecting for batch b, the local models of clients in
batches 1..b-1 are already fixed (from this round's selection), and clients
in batches b+1..B are excluded (not yet considered). The per-batch objective:

min_{w^n in W_t^n, for all n in P_t^b}
  1/(N - P + bP/B) * ( sum_{n in P_t^b} L_n(w^n) + sum_{n in (N-P_t) ∪ P_t^1 ∪...∪ P_t^{b-1}} L_n(w^n) )
  - (L/2) ||w||_2^2,
(Eq. 8)
where the aggregated model w for this step is the average over non-
participating clients plus the 1st-to-b-th batches of participating clients:
w = 1/(N - P + bP/B) * sum_{n in (N-P_t)∪P_t^1∪...∪P_t^b} w^n.
This is described as equivalent to selecting local models that are close to
those of clients participating in previous rounds, maintaining memory of
their data.
Proposition 3: The computation complexity of solving (8) is O(B K^{P/B}) and
the memory cost is KPC.

Practical control knobs noted in text: P/B can be held roughly constant to
keep complexity manageable; in the extreme, setting B = P makes complexity
LINEAR in K. The paper states experiments show even a small K (e.g. K=3)
gives satisfactory performance. Memory cost KPC is called manageable because
P is usually a small fraction of total clients and local models of non-
participating clients can be stored on disk (paper gives the illustrative
aside that a 1TB hard drive could store ~20,000 copies of ResNet-18).

--- Why no auxiliary/proxy dataset is needed ---
Unlike weight-setting methods (e.g. FedLAW) or ensemble-distillation methods
(e.g. FedDF, FedGEN) which may require an additional public/proxy dataset or
gradient descent / bipartite matching at the server, FedCDA's approach does
not depend on an auxiliary public dataset and does not introduce higher
computational complexity than existing methods.

--- Algorithm 1: FedCDA Algorithm (full pseudocode as given) ---
Input: Number of cached local models K, number of subsets B, learning rate
eta, number of sampling clients P, and total communication rounds T.
Output: Converged global model w.

1: Initialize the model parameter w_0;
2: Distribute w_0 to all clients;
3: for each communication round t in {1, 2, ..., T} do
4:    Randomly select a set of clients P_t;
5:    for each selected client n in P_t in parallel do
6:        Initialize the local model with the received global model: w^n = w_t;
7:        Solve the local problem by updating w_n for E local mini-batch SGD
          steps and accumulate the local loss F_n(w^n) in the last local
          epoch: w^n = w^n - eta * grad_{w^n} f_n(w^n);
8:    Update the cached set W_t^n for n in P_t by replacing the oldest model
       with received w^n;
9:    Select local models w^n for each client n in P_t by solving problem (8);
10:   Aggregate both selected and fixed local models to obtain:
       w_{t+1} = (1/N) sum_{n=1}^{N} w^n;
       return global model w_T

Text clarifies: FedCDA differs from FedAvg primarily in lines 9 and 10. When
it receives local models from a subset of clients, the server updates its
cached local models (line 8/9 of narrative numbering — replacing the oldest
round's local model with the most recently received one), then selects local
models for aggregation by solving problem (8) (line 9/10). The final global
model is obtained by AVERAGING both the newly selected local models (for
participating clients) and the fixed cached local models (for non-
participating clients) — this is a simple average over all N clients'
(selected or fixed) local models: w_{t+1} = (1/N) sum_{n=1}^{N} w^n.

--- Warmup period ---
"In practice, we usually apply FedCDA after a warmup training stage using
FedAvg or other baselines to ensure that the local models can approach the
convergence during the local training process." This is because the
approximation grad_{w^n}F_n(w^n) ~= 0 (used to go from Eq. 3 to Eq. 5) is
only good once local models are near convergence; using it on not-yet-
converged early-round local models is noted to potentially hurt training
(see Section 4/Experiments: Figure 4, "Warmup Analysis" discussed below).

--- Note on orthogonal techniques ---
The paper notes most existing methods also employ improved techniques "over
the step of line 11" [sic; likely refers to the final aggregation step], e.g.
re-setting aggregation weights (FedLAW) or ensemble distillation (FedDF,
FedGEN), and states these are ORTHOGONAL to FedCDA (i.e., could in principle
be combined, but FedCDA itself does not do server-side re-weighting or
distillation — it uses plain averaging over selected/fixed local models).

simple CNN described above (not used for CIFAR datasets).

--- 4.3 Data partitioning (non-IID) ---
Two non-IID partition schemes are used, both applied across datasets:
1. Shards (McMahan et al., 2017a): "the sorted samples are shuffled into
   N * S shards, and assigned to N clients randomly. Each client owns an
   equal number of pieces." S values tested: {2, 4, 8} (per Table 1 column
   headers: Shards (S) = 2, 4, 8).
2. Dirichlet (Lin et al., 2020): "data distribution over clients satisfies
   the Dirichlet distribution by using alpha to characterize the degree of
   heterogeneity. We set alpha of Dirichlet: {0.1, 0.3, 0.5}" (per Table 1
   column headers: Dirichlet(alpha) = 0.1, 0.3, 0.5).

--- 4.4 Baselines compared against ---
- FedAvg (McMahan et al., 2017a) — base method.
- "Efficient FL approaches" / local-process or LR-tuning methods:
  FedProx (Li et al., 2020), FedExP (Jhunjhunwala et al., 2023), FedSAM
  (Qu et al., 2022).
- Aggregation-category baselines, three sub-types:
  - Ensemble distillation: FedDF (Lin et al., 2020), FedGEN (Chen & Chao,
    2021).
  - Model fusion: FedMA (Wang et al., 2020a), GAMF (Liu et al., 2022).
  - Weight setting: FedLAW (Li et al., 2023).

--- Theoretical results (stated, proofs NOT available — Appendix B not in PDF) ---
- Theorem 1 (Approximation Selection Error): defines w^{n,*} as the local
  optimum closest to w_t^n, and D = max over all clients/rounds/cache-slot
  pairs of the distance between any two close cached local models. If
  ||w_t^n - w^{n,*}|| <= epsilon for a constant epsilon, then the gap in
  global loss between aggregating via the Eq. 5 approximation vs. the exact
  Eq. 3 objective is bounded: epsilon_gap <= 4*L*epsilon^2 + 2*L*D*epsilon.
  Implication stated: the approximation error shrinks as local models get
  more converged, i.e. with more local iterations or longer warmup — this is
  said to be verified by Figure 2(c) and Figure 4 (the Warmup figure,
  referenced in text as "Figure 6.2").
- Theorem 2 (Impact of Divergence of Local Optima): under strong convexity
  of F_n with parameter mu in the region spanning cached local optima to the
  global model, and assuming local loss is equal at local optima across
  rounds (F_n(w_t^{n,*}) = F_n(w_{t'}^{n,*})), IF the divergence among
  selected local models is small enough — Var(w_t^{n,*}) <= (mu/L) *
  Var(w_t^n) - (mu/L + 1) * epsilon^2 — THEN the global loss using the
  selected cross-round global model w_{t*} is lower than using the plain
  t-th-round global model w_t: F(w_{t*}) <= F(w_t). Paper notes this
  motivates why FedCDA may especially favor LARGE/overparameterized models,
  where local optima across clients can coincide (near-zero local loss), and
  states Table 1 results corroborate this (bigger improvement on larger
  models).
- Theorem 3 (Convergence on Non-convex Functions): under Assumptions 1-3 and
  learning rate eta satisfying 0 < eta <= 1/(LE) [E = local steps/epochs],
  the global model solved via Eq. 3 achieves asymptotic convergence:
  (1/T) * sum_{t=1}^{T} ||grad F(w_{t*})||_2^2 = O(1/sqrt(T)).
  Proof sketch only (full derivation in Appendix B.4, NOT in this PDF): shown
  by (a) bounding the loss gap between w_{t*} (from Eq. 3) and the reference
  global model w_t (plain aggregation of newest local models), then (b)
  showing w_t's loss converges, which transitively gives convergence for
  w_{t*}.
- Full proofs for Theorems 1-3 are stated to be in "Appendix B.1" / "B.2" /
  "B.4" respectively — NOT AVAILABLE IN THIS PDF.

--- Compute/communication cost discussion (from main body, Section 4 "Methodology") ---
- Complexity progression: brute-force Eq. 6 is O(K^N) (Prop. 1) -> partial-
  client restriction Eq. 7 is O(K^P) (Prop. 2) -> batch-based Eq. 8 is
  O(B*K^(P/B)) (Prop. 3). Memory cost is O(KNC) for Prop.1, then O(KPC) for
  Props. 2 and 3 (C = model size/parameter count).
  practical knob: keep P/B roughly constant, or set B=P for linear-in-K cost.
- Memory/storage framing: "the memory cost KPC is also manageable because K
  is small, because the number of sampled clients P is usually a small ratio
  of the total clients... local models of non-participated clients can be
  stored on disk which has sufficient storage space. For example, a 1TB hard
  drive can store approximately 20,000 copies of ResNet-18... we believe the
  cost is within the budget of the aggregation node which is typically hosted
  by a cloud."
- FedCDA is explicitly said NOT to require an auxiliary/proxy public dataset
  (unlike FedLAW, which needs a proxy dataset for learning aggregation
  weights, or FedDF/FedGEN-style ensemble distillation, which typically need
  an unlabeled proxy dataset or generated data). FedCDA also does not require
  server-side gradient descent (as FedLAW/FedGEN use) or solving a maximum
  bipartite-matching problem (as FedMA-style model-fusion methods use),
  keeping its computational overhead comparable to existing methods.

--- Conclusion / stated limitation (Section 7) ---
The paper's conclusion restates: FedCDA selectively aggregates cross-round
models with minimum divergence; an approximation selection algorithm is
introduced for efficiency; convergence is proven theoretically, and empirical
results outperform SOTA baselines.
Stated limitation/future work: "This paper addresses the ideal scenario
where smoothness value [L] is equal among clients. The goal is to improve
our method for cases with varying smoothness by refining objectives and
incorporating sharpness in cross-round aggregation, as we currently treat
all local models equally without considering the sharpness of their local
optima, despite flatter optima often correlating with better
generalization." — i.e., current FedCDA (and this extraction's Algorithm 1)
assumes a SINGLE SHARED L across all clients (L=1 was used in experiments),
not per-client smoothness; this is an explicitly acknowledged simplification/
limitation, not a hidden detail.
